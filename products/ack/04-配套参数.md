## 容器网络插件（CNI）Terway 与 Flannel

| 对比项 | Terway | Flannel |
|---|---|---|
| 容器网段来源 | 从 VPC 中分配（Pod IP 取自 Pod 交换机） | 指定的虚拟网段 |
| NetworkPolicy 网络策略 | 支持 | 不支持 |
| IPv4/IPv6 双栈 | 支持（含 Pod IPv6 公网带宽） | 不支持 |
| Pod 固定 IP / 独立交换机、安全组 | 支持 | 不支持 |
| Pod 绑定 EIP | 支持 | 不支持 |
| 多集群互访 | 支持（安全组放行即可） | 不支持 |
| 单节点最大 Pod 数 | 由 ECS 规格 ENI 数量决定 | 256（创建时指定，创建后不可改） |

- 容器网络插件在创建集群时安装，集群创建后不支持更改。
- 需强诉求（网络安全、固定 Pod IP、NetworkPolicy）选 Terway；集群规模较小（如 <500 节点）且无特殊网络需求可用 Flannel。

## 存储插件（CSI）

| 组件 | 职责 | 安装 |
|---|---|---|
| csi-plugin | 数据卷挂载、卸载；默认提供云盘、NAS、OSS 挂载能力 | 集群默认部署 |
| csi-provisioner | 存储卷自动创建（动态供给） | 集群默认部署 |

| 使用限制 | 内容 |
|---|---|
| 集群版本 | 需 1.14 及以上 |
| 操作系统 | 不支持 Windows 节点 |
| kubelet 参数 | --enable-controller-attach-detach 为 true |
| 授权（托管集群） | 使用 AliyunCSManagedCsiRole RAM 角色，Token 存于 addon.csi.token Secret |
| Flexvolume | 已停止维护，1.20 之后新建集群不再支持，需迁移 CSI |
| CNFS | Pro 版存储增强，将 NAS/OSS/CPFS 抽象为 CRD（子目录动态创建、配额、IO 监控、回收站、分布式缓存） |

## 存储类型参数（云盘 / NAS / OSS / CPFS）

| 存储方案 | 静态供给 | 动态供给 | 访问模式 | 关键限制 |
|---|---|---|---|---|
| 云盘 | 支持（PV/PVC） | 支持（StorageClass/PVC） | RWO（未启用多重挂载） | 三副本、9 个 9 可靠性；除 ESSD 同城冗余外只能挂同可用区 Pod；PVC 容量=实际分配容量，支持在线扩容 |
| NAS | 支持 | 支持 | RWX、RWO、ROX | NFS 协议；读写走网络有毫秒级延迟；不支持跨 VPC 挂载；动态 subpath 且 allowVolumeExpansion=true 时 PVC 容量转为目录配额 |
| OSS | 支持（ossfs 1.0/2.0） | 支持（ossfs 1.0/2.0） | RWX、ROX | FUSE 实现，高延迟低随机 I/O，不推荐数据库/高频写；PVC 容量不限制实际用量 |
| CPFS 智算版 | 支持 | 支持 | RWX | 邀测、部分地域；成本高；不支持跨 VPC 挂载 |
| CPFS 通用版 | 支持 | 不支持 | RWX | 成本高于通用 NAS、部分地域；仅 NFS、不支持跨 VPC |

节点故障恢复：云盘由 CSI 自动从旧节点卸载挂新节点；NAS/OSS/CPFS 共享存储在新节点直接重挂；HostPath 数据固定在原节点。

## Ingress 组件

| 组件 | 形态 | 关键事实 |
|---|---|---|
| ALB Ingress | 全托管（ALB 实例托管流量） | Controller 仅作控制面不转发流量；AlbConfig（集群级 CRD）与 ALB 实例一对一；Flannel 下后端仅支持 NodePort 与 LoadBalancer 类型 Service，不支持 ClusterIP；单 ALB 实例支持千万级连接、百万 QPS（官方口径）；勿在控制台手改 ACK 管理的 ALB 实例配置（会被同步覆盖） |
| Nginx Ingress | 自建维护 | 需自行运维；配置变更需 Reload 导致长连接闪断；扩容消耗集群内资源 |
| MSE Ingress | 托管网关 | 与 Nginx/ALB 对比另见官方选型文档 |

大规模集群注意：ALB Ingress 经 OpenAPI 驱动配置变更，批量操作可能出现延迟，变更前需容量评估与压测。

## ACR 镜像仓库集成

| 事实项 | 内容 |
|---|---|
| 集成方式 | 镜像上传 ACR（个人版/企业版）；工作负载通过 imagePullSecrets 引用 Secret 拉取私有镜像 |
| Secret 创建 | kubectl create secret docker-registry，--docker-server 填 ACR 实例地址，需与镜像地址网络类型（内网/公网）相同 |
| 命名空间约束 | Secret 需与工作负载处于同一命名空间 |
| 免密组件 | 2024-09-09 及之后新建的 ACR 个人版不支持免密组件，需用 Secret 方式 |
| 免密 vs 手动 | 免密组件不支持与手动填入 imagePullSecrets 同时使用（冲突会导致拉取失败） |
| 引用位置 | Service Account 的 imagePullSecrets 字段或工作负载 Pod spec 的 imagePullSecrets 字段 |
| 公网拉取 | 需集群开启公网访问能力且公网 IP 带宽峰值足够；海外源（Docker Hub）可能慢/失败，可用 ACR 制品订阅、GA 加速或第三方 mirror |
