## Pod CIDR 与 Service CIDR 规划

| 网段 | 配置规则 | 可否修改 |
|---|---|---|
| 容器网段（Pod CIDR，仅 Flannel） | 为 Pod 分配 IP 的地址池；不能与 VPC 及 VPC 内已有 ACK 集群网段重叠，不能与服务网段重叠 | 创建后不可更改（✗） |
| 节点 Pod 数量（仅 Flannel） | 定义单节点最大 Pod 数 | 创建后不可更改（✗） |
| Pod 交换机（仅 Terway） | Pod IP 从该交换机分配；与 Worker 节点交换机需在同一可用区；网段掩码建议 ≤19、最大 ≤25，否则可分配 Pod IP 过少 | 支持修改（✓） |
| 服务网段（Service CIDR） | 集群内部 Service 地址池；不能与 VPC 及已有集群网段重复，不能与容器网段重叠；服务地址仅集群内可用 | 创建后不可修改 |
| IPv6 服务网段 | 须用 ULA 地址，范围 fc00::/7 内，前缀长度 112~120；推荐与服务网段可用地址数相同 | 仅开启 IPv6 双栈时配置 |
| IPv6 双栈 | 仅支持 1.22 及以上、仅 Terway；VPC 须支持双栈；Worker 与控制面通信仍用 IPv4 | 创建后不可更改（✗） |

官方示例（Terway 单可用区）：VPC 192.168.0.0/16、节点交换机 192.168.0.0/19、Pod 交换机 192.168.32.0/19、服务网段 172.21.0.0/20、最大可分配 Pod 地址数 8192。

VPC 主网段推荐 RFC 标准私网：192.168.0.0/16、172.16.0.0/12、10.0.0.0/8 及其子网，掩码有效范围 8~28 位；公网网段建 VPC 需配额白名单。集群本地域名默认 cluster.local。

## VPC 与集群网络规模

| 规划项 | 默认/限制 |
|---|---|
| 单地域 VPC 数量 | 默认 10 个（可配额提升） |
| 单 VPC 交换机数量 | 默认 150 个（可配额提升） |
| Flannel 集群单路由表自定义路由条目 | 200 条（不含动态传播路由） |
| 单 VPC 安全组私网 IP 容量 | 普通安全组 6,000；企业级安全组 65,535 |

集群规模与网络规划：

| 节点规模 | 适用场景 | VPC 规划 | 可用区规划 |
|---|---|---|---|
| <100 节点 | 非核心业务 | 单 VPC | 1 个（推荐 2 个及以上） |
| ≥100 节点 | 一般业务、多可用区 | 单 VPC | 2 个及以上 |
| ≥100 节点 | 核心业务、多地域 | 多 VPC | 2 个及以上 |

多集群规则：同一 VPC 内多集群的 Pod 网段不能重叠，服务网段可重叠；跨 VPC 互联的新集群网段不能与各 VPC 网段、其他集群及其 Pod 网段重叠。

## Service 类型与 LoadBalancer

| 类型 | 说明 | 计费 |
|---|---|---|
| ClusterIP（默认） | 集群内部虚拟 IP，仅集群内访问 | 不计费 |
| NodePort | 节点开放端口，端口范围默认 30000-32767，四层转发 | 不计费；公网访问需绑 EIP（按 EIP 计费） |
| LoadBalancer | 基于 NodePort 增加外部负载均衡器，自动提供外部 IP；支持 TCP/UDP 四层，可扩展 HTTP/HTTPS 七层 | 负载均衡实例计费（CLB/NLB） |
| Headless Service | 无虚拟 IP，DNS 直接返回 Pod IP 列表 | 不计费 |
| ExternalName | 内部服务名映射到外部域名 | 不计费 |

- 创建 LoadBalancer Service 时，集群控制面自动与负载均衡服务交互创建负载均衡器实例。
- Cloud Controller Manager 版本 ≥ v2.5.0 时，控制台创建 Service 的 CLB 实例选项变为白名单功能且仅支持按使用量计费；需经配额平台申请。
- 集群内访问应优先用 ClusterIP；集群内直接访问 LoadBalancer IP 行为不一致（受 CNI、kube-proxy 模式、externalTrafficPolicy 影响）。

## 外部流量策略（externalTrafficPolicy）

| 比较项 | Local | Cluster |
|---|---|---|
| 后端挂载（Flannel） | 仅 Pod 所在节点挂负载均衡后端 | 集群所有节点挂载后端 |
| 负载均衡配额消耗（Flannel） | 较少 | 大量消耗 |
| 集群内访问 Service | 仅后端 Pod 所在节点可访问 | 任意节点可访问 |
| Pod 负载均衡（Flannel） | 默认不均衡，需 Annotation 指定 wrr | 默认均衡 |
| 保留来源 IP / 会话保持（Flannel） | 支持 / 支持 | 不支持 / 不支持 |
| Terway 下 Pod 挂载 | Pod 直接挂负载均衡后端（Local/Cluster 相同） | 同左 |

Flannel + IPVS + Local 在 K8s <1.24 时集群内访问无后端节点会失败；≥1.24 允许回退 Cluster 行为。

## SLB 集成与 Ingress 入口

| 场景 | 负载均衡资源 |
|---|---|
| API Server 访问入口 | ACK 自动新建按量付费私网 CLB 实例（必选，不可复用、不可删除，删除后 API Server 无法访问且无法恢复）；可选绑 EIP 暴露公网；2024-12-01 起新建 CLB 不再支持包年包月并新增实例费 |
| LoadBalancer 类型 Service | 自动创建/配置 CLB，或经 Annotation 用 NLB |
| Nginx Ingress | 通过 Service 自动创建 CLB（可配 Annotation 换已有 SLB） |
| ALB Ingress | 关联 ALB 实例（创建时自动建标准版按量付费公网/私网 ALB，配 HTTP:80 监听） |

- 服务转发模式（kube-proxy）可选 iptables / IPVS / nftables，创建后不可更改；1.35 起 ipvs 模式被标记弃用，nftables 要求节点 Linux 内核 ≥5.13。
- 安全组入方向需放行 100.64.0.0/10（用于访问阿里云其他服务，执行镜像拉取、查询 ECS 基础信息）。

- ALB Ingress 的 Flannel 后端限制：仅 NodePort 与 LoadBalancer 类型 Service，不支持 ClusterIP。
- 集群公网出口：NAT 网关（节点池公网访问出口）；单节点公网可用 EIP。
