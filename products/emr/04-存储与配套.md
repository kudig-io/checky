## 存储架构选型：HDFS vs OSS-HDFS/OSS

| 对比维度 | 存算分离（OSS-HDFS/OSS） | 存算一体（HDFS） |
|---|---|---|
| 技术特点 | 计算与存储独立扩展，数据持久化在 OSS-HDFS/OSS，完全兼容 HDFS 接口 | 计算与存储耦合，数据存于集群内 HDFS |
| 适用场景 | 数据湖架构、冷数据分析 | 低延迟读写场景 |
| 数据可靠性 | OSS 本地冗余/同城冗余，跨可用区高可靠 | 副本机制：本地盘默认 3 副本、云盘默认 2 副本；限于集群内部，无跨区域容灾 |
| 数据持久性 | 99.9999999999%（12 个 9），集群释放后仍长期保留 | 随集群释放而删除 |
| 扩展灵活性 | 计算与存储解耦，计算节点独立扩缩 | 扩缩容需同步调整；缩容需逐台下线，扩容需重平衡 |
| 存储成本（官方示例） | 0.12 元/GB/月（标准 OSS 存储）；OSS-HDFS 辅助数据也计 OSS 存储费 | 0.35 元/GiB/月（块存储） |
| 运维 | 计算节点无状态，可快速替换；存储容量无需随数据增长调整集群 | DataNode 故障需手动重平衡；扩缩容需人工调整集群规模 |
| 访问方式 | `oss://bucket-name.endpoint/path/to/data` | HA：`hdfs://namespace/path`；非 HA：`hdfs://namenode-host:port/path` |

## 磁盘配置与容量评估

| 磁盘角色 | 说明 | 支持类型 |
|---|---|---|
| 系统盘 | 安装操作系统，不保存业务数据 | 云盘 |
| 数据盘 | 存储数据、本地化日志、任务 Shuffle；容量按存储架构差异化评估；多盘配置比单盘更提升组件可用性 | 云盘、本地盘 |

| 云盘类型 | 性能口径 | 典型场景 |
|---|---|---|
| ESSD 云盘 | 高 IOPS/吞吐，毫秒级延迟 0.2 ms，支持 PL0~PL3 | 时延敏感、I/O 密集（OLTP、NoSQL、Elasticsearch） |
| SSD 云盘 | 较高 I/O，延迟 0.5~2 ms | I/O 密集应用、中小型关系型/NoSQL 数据库 |
| 高效云盘 | 中等 I/O，延迟 1~3 ms | 开发测试、系统盘 |
| 本地盘 | 物理直连本地硬盘，极低延迟高吞吐；**仅适用于 Core 或 Task 节点**，有数据丢失风险 | 大数据型/本地 SSD 机型的数据盘 |

容量评估（官方计算规则）：

| 数据类型 | 计算规则 |
|---|---|
| 原始数据 | 存储空间 = 原始数据量 |
| 中间数据 | 原始数据量 × 1.5（按业务复杂度调整） |
| 结果数据 | 原始数据量 × 10%~50%（按业务需求调整） |
| 增长规划 | 至少考虑 6 个月数据增长 |
| 存算一体（HDFS） | 需再叠加副本冗余（默认 3 副本） |
| 存算分离 | 数据盘仅用于临时缓存、本地日志与 Shuffle，不保留业务数据 |

- ESSD 云盘在创建集群时默认性能级别 PL1；系统盘支持 PL0/PL1/PL2，数据盘支持 PL0/PL1/PL2/PL3。
- 控制台「选择硬件与网络」口径：Master 节点不支持增加磁盘数量，只能调大单块磁盘容量或扩容 Core。

## 配套服务与作业入口

| 配套 | 官方口径 |
|---|---|
| DataWorks | EMR 与 DataWorks 集成，可在 DataWorks 上以 EMR 作为作业计算与数据存储引擎 |
| EMR Workflow | 全托管工作流与任务调度服务（单独计费，见 07 篇） |
| 元数据 | DLF 统一元数据（推荐）、自建 RDS、内置 MySQL（不推荐生产使用） |
| 服务运行日志采集 | 创建集群时可一键开启/关闭，**默认开启**；关闭后 EMR 健康检查与技术支持受限 |
| Web UI 访问 | 组件 Web 界面端口默认不对外开放；通过 Knox 代理访问需集群支持并添加 KNOX 服务（详见 05 篇） |
| Hue | 使用限制页将 Hue 与 Ranger 并列为依赖内置 MySQL 的组件；发行版本矩阵未列 Hue，版本口径 ⚠️ 待核 |
| 第三方软件 | 建议通过集群创建时的引导操作安装；创建后手工安装的软件在扩容新节点时需重新安装 |
