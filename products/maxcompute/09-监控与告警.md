# MaxCompute · 监控与告警

> 产品：MaxCompute ｜ 口径：公共云 ｜ 复核：2026-11-17

## 核心监控指标

MaxCompute 已接入云监控（CloudMonitor），在云监控控制台按产品「MaxCompute-包年包月计算Quota」「MaxCompute-通用」「MaxCompute-包年包月数据传输服务」创建报警规则或配置监控大盘。

- 官方文档以中文「监控项」名称发布指标；云监控 API 的英文 MetricName 取「指标和事件中心」页签 Metric ID 列，官方文档未公开 MaxCompute 各监控项的英文 MetricName ⚠️ 待核。
- 作业运行时长类指标支持地域：杭州、上海、北京、张家口、深圳、乌兰察布、成都、中国香港、硅谷、弗吉尼亚、吉隆坡、东京、法兰克福、雅加达、伦敦、新加坡（共 16 个）。
- 运行时长小于 1 分钟的作业无法被作业运行时长指标监控到。

| 指标（官方名称） | 含义 | 单位 | 统计周期 | 维度 |
|---|---|---|---|---|
| 1级配额CPU使用率 | 一级 Quota 的 CPU 使用量占总量（预留 CU + 弹性预留 CU）的百分比 | % | 每分钟采集一次 | MaxCompute-包年包月计算Quota / level1（一级配额组实例） |
| 1级配额CPU使用量 | 一级 Quota 的 CPU 总使用量 | core | 每分钟采集一次 | level1（一级配额组实例） |
| 1级配额MEM使用率 | 一级 Quota 的内存使用量占内存总量（预留 + 弹性预留）的百分比 | % | 每分钟采集一次 | level1（一级配额组实例） |
| 2级配额作业等待数 | 二级 Quota 的作业等待数（CPU 使用量高且等待数多时可能需人工干预资源） | count | 每分钟采集一次 | level2（二级配额组实例） |
| Tunnel上传流量_项目级别 | 以项目为单位的实时上传流量，可设最大上传流量阈值触发报警 | bytes/min | 官方未标注采集周期 ⚠️ 待核 | MaxCompute-通用 / 项目 |
| Tunnel日累计下载数据量_项目级别 | 以项目为单位、单日累计下载的数据量，可设最大数据量阈值 | MB | 日累计 | MaxCompute-通用 / 项目 |
| Tunnel当前并发数（Slot）_租户级别 | 以租户为单位当前使用的并发数（Slot），可设阈值触发报警 | count | 官方未标注采集周期 ⚠️ 待核 | MaxCompute-通用 / 租户 |
| 作业运行时长 | 项目下所有作业的运行时间（含等待时间），超过阈值按报警规则通知；运行时长 <1 分钟无法监控 | 时间（官方未标注单位 ⚠️ 待核） | 官方未标注统计周期 ⚠️ 待核 | MaxCompute-通用 / 项目 |
| 作业运行时长_SQL类型 | 同上，仅监控 SQL 类型作业；另有「作业运行时长_SQL类型_提交人」变体，报警内容额外含提交人 | 时间（官方未标注单位 ⚠️ 待核） | 官方未标注统计周期 ⚠️ 待核 | MaxCompute-通用 / 项目 |
| 按量付费作业的日消费（CNY） | 单日累计 SQL、MapReduce 作业消费金额，可设最大日消费金额阈值 | CNY（元） | 日累计 | MaxCompute-通用 / 项目 |
| StorageAPIRead日消费量 | 单日累计 Storage API 读取数据消费量（每租户每月 1 TB 免费读写额度，超 1 TB 后开始监控） | GiB | 日累计 | MaxCompute-通用 / 项目 |
| 标准存储大小_项目级别 | 项目的标准存储大小 | GB | 每小时采集一次 | MaxCompute-通用 / 项目 |

- 同族指标还有：2级配额CPU/MEM 使用率与使用量、Tunnel下载流量_项目级别、Tunnel日累计上传数据量_项目级别、作业运行时长（全类型）、StorageAPIWrite 日/月消费量、按量付费作业的月消费（CNY）、低频/长期存储大小_项目级别、低频存储最近 30 天访问量百分比、长期存储最近 180 天访问量百分比、1级配额并发 slot 使用率（数据传输服务独享资源组维度）。
- 云监控数据保留时长随 Period 而定（Period=60 秒存储 31 天）。

## 官方默认与推荐告警

**A. 官方文档示例阈值**

| 场景 | 阈值 / 规则（官方示例） | 出处 |
|---|---|---|
| 包年包月配额组 CPU 使用率 | 示例：配额组配置 150 CU，满 1 核按 100% 计、最大使用量 15000%，监控阈值设为「大于 12000%」则报警；收到报警表示资源组即将满负荷，继续提交作业可能出现排队 | 监控报警（报警规则配置示例） |
| 单 SQL 消费限制 | 官方设置建议示例：Project 级 `SETPROJECT odps.sql.metering.value.max=100`（m_value = SQL 读取量 GB × SQL 复杂度）；按金额换算时 `m_value = 确定的金额（元）/0.3` | 消费监控告警 |
| 日累计 SQL 消费限制 | 官方示例：`SETPROJECT odps.costcontrol.rule={"byDate":{"sql":100}}`（Limit 为日累计金额阈值，单位：元，以东八区当日 00:00:00~23:59:59 计） | 消费监控告警 |
| 历史高额消费预警 | 费用与成本 > 成本预警 > 高额消费预警：选择预警商品并填写预警阈值（阈值由用户自填，官方未给推荐值） | 消费监控告警 |

**B. 官方缺位项**

- 作业运行时长（全类型 / SQL 类型）、Tunnel 流量与并发、存储大小、Storage API 消费、按量消费等云监控指标阈值告警：**官方未发布推荐阈值** 📋 待补（官方文档仅提供配置步骤与上表示例，按阈值红线不收经验值）。
- 作业超时监控的推荐时长阈值：**官方未发布推荐阈值** 📋 待补。

## 通知与渠道

| 渠道 / 机制 | 说明 |
|---|---|
| MaxCompute 报警通知方式 | 云监控报警服务支持电话、短信、邮件和钉钉机器人 |
| 消费告警通知 | 实时消费监控超阈值通过电话、短信、邮件或钉钉通知；历史高额消费预警在第二天 09:00 左右以短信通知 |
| 报警联系人与联系组 | 云监控控制台「报警服务 > 报警联系人」创建联系人/联系组，创建报警规则时选择联系人组 |
| 报警联动 | 报警规则支持联动弹性伸缩、轻量消息队列（MNS）、函数计算、日志服务（SLS）；Webhook 回调以 HTTP POST 推送报警信息 |
| 通道沉默周期与生效时间 | 创建报警规则时可设置通道沉默周期、生效时间（沉默期内不重复发送，超期未恢复再次发送） |
| 告警升级 | 事件中心「通知配置」可按 Critical / Warn / Info / 恢复级别分别设置通知组实现升级（云监控通用能力；MaxCompute 专属升级策略官方未发布 📋 待补） |
| MaxCompute 侧处理入口 | MaxCompute 控制台概览页右侧「告警与风险提示」查看各指标告警数量；作业超时报警按通知中的 InstanceID 到「观测运维 > 作业运维」定位，DataWorks 提交的节点转 DataWorks 运维中心处理 |
| RAM 权限 | RAM 用户执行配置监控告警操作需 AliyunCloudMonitorFullAccess（另需云监控服务本身权限） |
