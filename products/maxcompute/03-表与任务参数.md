# MaxCompute · 表与任务参数

> 产品：MaxCompute（原 ODPS） ｜ 口径：公共云 ｜ 复核：2026-11-16

## 表与分区上限

| 限制项 | 最大值/条件 | 说明 |
|---|---|---|
| 单表列定义数 | 1200 个 | 列定义个数上限 |
| 单表分区数 | 60000 个 | 超出后无法再写入数据 |
| 表的分区层级 | 6 级 | 分区层次不能超过 6 级 |
| 单次查询分区个数 | 10000 个 | 最多查询分区个数不能超过 10000 |
| 表名长度 | 128 字节 | 字母开头，仅小写字母、大写字母、数字、下划线 |
| 列名长度 | 128 字节 | BigQuery 兼容模式（`SET odps.sql.bigquery.compatible=true;`）下为 256 字节 |
| 注释长度 | 1024 字节 | — |
| 单元格（列记录）长度 | 8 MB | STRING 字段上传也受此限制 |
| 动态分区生成数 | INSERT INTO ≤10000 个；INSERT OVERWRITE ≤60000 个 | 分布式环境下单进程最多输出 512 个动态分区 |
| 表分区创建频率 | 120 次/15 秒 | `ALTER TABLE ... ADD PARTITION` |

- MaxCompute产品使用限制：https://help.aliyun.com/zh/maxcompute/product-overview/limits-4 ｜ 复核：2026-11-16
- 插入或覆写动态分区数据（动态分区限制）：https://help.aliyun.com/zh/maxcompute/user-guide/insert-or-overwrite-data-into-dynamic-partitions ｜ 复核：2026-11-16

## 单任务（SQL 作业）限制

| 限制项 | 最大值/条件 |
|---|---|
| SQL 语句长度 | 2 MB（含 SDK 调用场景） |
| SQL 执行计划长度 | 1 MB，超出报 ODPS-0010000 |
| 单作业最大执行时间 | 默认 24 小时，`SET odps.sql.job.max.time.hours=72;` 最长调到 72 小时，超时自动停止 |
| 屏显行数 | SELECT 屏显最多 10000 行 |
| MULTI-INSERT 目标表数 | 256 个 |
| UNION ALL 表数 | 256 个 |
| MAPJOIN 小表数 | 128 个 |
| MAPJOIN 内存 | 所有小表合计 ≤512 MB |
| ptinsubq 子查询返回 | ≤1000 行 |
| IN 参数个数 | 1024（建议值，非硬限制） |
| jobconf.json | 1 MB |
| 视图 | 不可写，不支持 INSERT |
| 列数据类型/位置 | 不可修改 |

**来源**：
- MaxCompute产品使用限制（SQL 限制）：https://help.aliyun.com/zh/maxcompute/product-overview/limits-4 ｜ 复核：2026-11-16

## MapReduce 作业限制

| 边界 | 值 |
|---|---|
| Instance 内存占用 | [256 MB, 12 GB]；默认框架内存 2048 MB + JVM Heap 1024 MB |
| 单 Job 引用 Resource 数 | ≤256 个（Table/Archive 按 1 个计） |
| 输入路数 / 输出路数 | ≤1024 / ≤256（输入表个数 ≤64） |
| 自定义 Counter 数 | ≤64；Group Name + Counter Name 长度和 ≤100 |
| Map Instance 数 | [1, 100000]，`odps.stage.mapper.num` 可配 |

Graph 使用限制（历史口径，功能已停止运维）：单 Job Worker 数最大 1000；单 Worker 占用 CPU 默认 200（范围 [50,800]）、内存默认 4096 MB（范围 [256 MB,12 GB]）；split_size 默认 64 MB。

**来源**：
- MaxCompute产品使用限制（MapReduce 限制）：https://help.aliyun.com/zh/maxcompute/product-overview/limits-4 ｜ 复核：2026-11-16
- Graph 使用限制（已停止运维）：https://help.aliyun.com/document_detail/27905.html ｜ 复核：2026-11-16

## 小文件官方数字

| 项 | 官方数字 |
|---|---|
| 小文件定义 | 分布式文件系统按块（Block）存放，块大小默认 64 MB，小于块大小的文件即小文件 |
| 可合并判定 | 分区含 100 个以上文件且平均文件大小小于 64 MB |
| 单 Fuxi Instance 读取 | 默认最多处理 100 个小文件，`odps.sql.mapper.merge.limit.size` 控制读取总大小 |
| 小文件大小阈值参数 | `odps.merge.smallfile.filesize.threshold`，全局默认 `odps_g_merge_filesize_threshold` = 32 MB（设置须 >32 MB） |
| 合并输出文件阈值 | `odps.merge.maxmerged.filesize.threshold`，全局默认 500 MB（设置须 >500 MB） |
| 即时合并命令 | `ALTER TABLE <table_name> [partition (...)] MERGE SMALLFILES;` |
| 查看文件数 | `desc extended <table_name> [partition (...)]` 看 FileNum/Size |
| 常见产生源 | Reduce 计算结果、Tunnel 采集、作业临时文件、回收站过期文件等 |
| 预防建议 | Tunnel SDK 缓存满 64 MB 提交一次；避免频繁上传小文件；分区表设置生命周期 |

**来源**：
- 合并小文件：https://help.aliyun.com/zh/maxcompute/user-guide/merge-small-files ｜ 复核：2026-11-16

## PyODPS（DataWorks 内）限制

| 限制项 | 值 |
|---|---|
| 节点本地处理数据 | ≤50 MB |
| 节点运行内存 | ≤1 GB，超出任务被系统中止（Got killed） |
| 第三方库 | 仅纯 Python 库与 Numpy；非自定义函数代码可用平台预装 Numpy/Pandas |
| instance tunnel | DataWorks 中 `options.tunnel.use_instance_tunnel` 默认 False |
