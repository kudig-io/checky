# MaxCompute · 计算类型与规格

> 产品：MaxCompute（原 ODPS） ｜ 口径：公共云 ｜ 复核：2026-11-16

## 计费模式与规格类型

| 规格类型 | 计算资源 | 存储/上传下载 | 计费规则 | 适用场景 |
|---|---|---|---|---|
| 包年包月标准版 | 预留计算资源（独享）+ 非预留计算资源（非必选，已停售） | 共享型，按需存储无限制 | 计算（包年包月）+ 存储 + 公网下载 | 已上线、可平稳运行的项目 |
| 弹性预留 CU | 预留独享，必须先有包年包月预留资源才可扩容 | 不涉及 | 计算（按时计费） | 每日高峰时段扩容、低谷缩容 |
| 自动弹性 CU | 弹性计算资源，必须先有包年包月预留资源 | 不涉及 | 计算（按时计费） | 负载波动频繁、峰谷难预测 |
| 按量付费标准版 | 共享型，作业按需抢占，不可指定用量 | 共享型按需存储 | 计算（按量）+ 存储 + 公网下载 | 作业量不稳定、需灵活存储 |
| 按量付费闲时版 | 与按量标准版资源共享，与包年包月隔离 | 不涉及 | 计算（按量，单价更低） | 极低成本、对完成时间不敏感的作业 |

已停售规格：包年包月套餐版（存储密集型 160/320/600）、包年包月非预留计算资源、按量付费开发者版，均于 2023-10-31 00:00:00 停止服务。

CU 定义：1 CU = 1 CPU Core + 4 GB 内存。

## 计算类型对比

| 计算类型 | 说明 | 按量计费（公共云） |
|---|---|---|
| SQL | 标准 SQL 开发，支持 DDL/DML/内建函数/UDF/MCQA 查询加速/物化视图 | 标准版：输入数据量 × SQL 复杂度 × 单价；≤100 TB/日 0.3 元/GB，超 100 TB 部分 0.285 元/GB，超 500 TB 部分 0.27 元/GB |
| SQL（闲时版 SpotSQL） | 使用按量付费闲时版配额的 SQL 作业 | 一般 0.1 元/GB |
| SQL（外部表） | OSS/OTS/Hologres/HBase/JDBC/HDFS 等外部表作业 | 按逻辑 size：0.03 元/GB |
| 查询加速 SQL（MCQA） | 短查询加速 | 0.3 元/GB；取消的查询不计费 |
| MapReduce | 原生 MR 及扩展 MR 编程接口 | 标准 0.36 元/计算时；Spot 0.154 元/计算时；计算时 = 运行小时 × Core 数 |
| Graph | 面向迭代的图计算框架 | **2026-07-22 起停止运维**，过渡期内存量作业可运行，建议迁移 |
| Spark | Spark on MaxCompute，兼容开源 Spark | 按计算时计费（杭州/北京/深圳已开通按量） |
| MaxFrame | Python 分布式计算框架，兼容 Pandas 算子 | 按量计费（计费规则见按量页） |
| Mars（数据科学） | 分布式 DataFrame/Tensor | **产品已下线**（2026-02-24 公告下线计费项），迁移至 MaxFrame |

SQL 复杂度系数：关键字个数 ≤3 → 1；4~6 → 1.5；7~19 → 2；≥20 → 4。关键字个数 = JOIN + GROUP BY + ORDER BY + DISTINCT + 窗口函数 + MAX(INSERT/UPDATE/DELETE 个数, 1)。

MapReduce 计费口径：1 CU = 4 GB 内存 + 1 CPU Core；一个 Map/Reduce 作业默认占用 2 Core、3 GB 内存；失败作业与排队时间不计费。

## 选型速查

| 场景 | 官方建议 |
|---|---|
| 新用户/初期用量少 | 先用按量付费，买预留 CU 会闲置 |
| 项目测试阶段 | 按量付费成本更低 |
| 已上线、要求稳定 | 包年包月预留计算资源（独享、不抢占公共资源池） |
| 大部分时段固定 + 短时激增 | 包年包月 + 按时计费（弹性预留/自动弹性）扩容 |
| 极低成本、时间不敏感 | 按量付费闲时版 |
| 每日定时高峰 | 弹性预留 CU（定时扩缩容）；未及时缩容即使未使用也会计时收费 |
