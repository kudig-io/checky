## 数据校验

三种校验方式：全量校验（存量数据）、结构校验（库表结构）、增量校验（同步/迁移增量任务中源库 DML 变更对象）。三者均支持不停服校验，支持异构数据库间校验。

| 参数 | 取值 / 规则 |
|---|---|
| 全量校验模式 | 按行抽样进行全字段校验（抽样百分比 10~100 的整数，100% 即全量对比）；按表行数进行校验（只比行数不比内容） |
| 全量校验时间规则 | 当前仅支持「立即开始」 |
| 全量校验超时 | 不设置（不强制结束）或 1~72 的整数（小时），超时强制结束 |
| 全量校验基准 | 默认（源+目标合集）/ 源库 / 目标库 |
| 限速参数 | 全量校验每秒读取最大数据行数 RPS、每秒读取最大数据量 MBps；两者均为 0 表示不限速 |
| 单表差异行数上限 | 超过 100,000 行差异时，DTS 终止对该表的校验 |
| 无主键且无唯一索引的表 | 数据超过 10,000 行时不做校验；增量校验直接不做 |
| 空表 | 目标表为空表不校验 |
| 少量数据抽样 | 按行抽样对少量数据校验时抽样百分比不生效，默认 100%；MongoDB 抽样固定 100% 且不可修改 |
| SQL Server 无主键表 | 全部列作校验条件可能超过 2100 个参数上限导致报错 |
| 执行条件 | 建议源/目标 CPU 负载 30% 以下的业务低峰期执行 |
| 不支持场景 | 经典网络实例的增量校验；多表归并实例；已完成状态实例；物化视图；校验任务列表中配置的任务不做增量校验 |
| 计费 | 按表行数校验不收费；按行抽样全字段校验按实际校验数据量收费；增量校验任务暂停期间也收费 |

支持链路（节选）：全量校验覆盖 MySQL、PolarDB MySQL、PolarDB-X 2.0、PostgreSQL、PolarDB PostgreSQL（含兼容 Oracle）、MongoDB 三类架构、Tair/Redis 两类架构、SQL Server、Oracle、Db2 for LUW、Db2 for i、TiDB、AnalyticDB MySQL 等组合；增量校验与结构校验的组合更少，双向同步链路也支持校验。

## 迁移切换（业务切换流程）

前提：迁移任务处于「迁移中」或「已完成」状态；需停止数据库写入并暂停业务，官方建议在业务低峰期操作。

| 步骤 | 动作 | 关键阈值 |
|---|---|---|
| 1 | 等待进度变更为「增量迁移」，显示「无延迟」或延迟低于 5 秒 | < 5 秒 |
| 2 | 暂停业务，禁止写入源库 | — |
| 3 | 登录源库查会话（MySQL `show processlist` 等 6 种数据库命令），确认无写入会话 | — |
| 4 | 等待增量迁移再次「无延迟」并保持 ≥ 1 分钟后手动暂停任务 | ≥ 1 分钟 |
| 5 | 保持业务中断状态，解除源库禁写限制 | — |
| 6 | 创建并启动反向迁移任务（仅勾选「增量数据迁移」），作为回退方案 | 反向任务只能选增量 |
| 7 | 业务切换至目标库后，手动结束或释放该 DTS 迁移任务 | — |
| 8 | 出现问题可随时切回源库（反向任务持续回迁） | — |

- 迁移任务暂停期间不要随意启动，否则可能导致数据不一致。
- 迁移完成后应删除迁移账号或回收其写权限；DTS 会尝试恢复 7 天内运行失败的实例，切换前务必结束/释放任务或回收写权限，防止被自动恢复后覆盖目标库数据。

## 任务链路：同步拓扑与多级串联

| 拓扑类型 | 说明 | 需购买的同步实例数（官方示例） |
|---|---|---|
| 一对一单向同步 | 基础拓扑；目标实例的同步对象只读勿写 | 1 |
| 一对多单向同步 | A→B、A→C、A→D | 3 |
| 级联单向同步（多级串联） | A→B，再 B→C；前一级的目标实例是后一级的源实例 | 2 |
| 多对一单向同步 | B、C、D→A | 3 |
| 一对一双向同步 | 同一主键/业务主键/唯一键的记录只在一个实例中更新 | 正+反向任务 |

- 单向同步目标实例只读勿写，否则可能数据不一致。
- 多对一：不同源的多条变更指向目标同一行时，DTS 在目标端并发执行（非按序），可能不一致；多源汇聚主键冲突可通过参数 `sink.conflict.strategy` 设置为 `replace`（覆盖写入），默认 `insert`（不覆盖）。
- 双向同步限制：仅支持两个数据库之间；暂不支持跨境双向同步；仅正向任务同步 DDL；MongoDB、Tair/Redis 仅阿里云实例（接入方式为云实例）支持双向。
- 双向同步支持组合（官方配置文档齐备的）：MySQL↔MySQL、MySQL↔PolarDB MySQL、PolarDB MySQL↔PolarDB MySQL、PostgreSQL↔PostgreSQL、RDS PostgreSQL↔PolarDB PostgreSQL、PolarDB PG 互同步、PolarDB PG（兼容 Oracle）互同步、PolarDB-X 2.0 互同步、Tair/Redis 互同步、MongoDB 副本集互同步、MongoDB 分片集群互同步；PolarDB MySQL→MySQL 方向标注「文档准备中」。
- 单向同步可在线升级为双向同步。

## 双向同步任务配套限制

- DTS 会在源和目标库中建立数据库 `dts` 防止循环同步，任务期间勿修改该库。
- 两个任务互为源/目标时：仅允许其中一个任务同步全量+增量，另一个仅同步增量。
- 反向任务的源/目标实例「实例地区」不可修改；反向任务不支持正向任务「已选择对象」中的对象；反向配置不建议使用映射功能。
- 跨账号双向同步仅支持：RDS MySQL 实例间、PolarDB MySQL 集群间、Tair（企业版）实例间、MongoDB 副本集间、MongoDB 分片集群间。
- 双向同步实例在成都/上海地域且含全量任务时，DTS 默认创建「按表行数进行校验」的全量校验任务。
