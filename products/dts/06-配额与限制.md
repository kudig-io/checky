## 任务级硬限制

| 限制 | 数值 / 口径 |
|---|---|
| 双向同步数据库个数 | 仅支持两个数据库之间；暂不支持多个数据库双向 |
| 跨境双向同步 | 暂不支持 |
| 双向同步 DDL | 仅正向任务支持同步 DDL，反向任务不支持 |
| 双向同步跨账号 | 仅 RDS MySQL 间、PolarDB MySQL 集群间、Tair（企业版）间、MongoDB 副本集间、MongoDB 分片集群间 |
| 失败实例自动恢复 | 尝试恢复 7 天内运行失败的实例 |
| 技术支持恢复时效 | 运行失败后技术支持在 8 小时内尝试恢复（可能重启、调整实例参数） |
| 全量阶段主备切换 | 全量阶段不支持数据库实例主备切换，需重新配置任务 |
| IPv6 | 仅接受 IPv4 地址 |
| 迁移实例付费方式 | 仅支持按量付费（后付费），不支持转换计费方式 |
| 库表结构任务 | 不修改存储过程/函数的 routine_body、视图的 select_statement（异构或列映射时需手动处理） |

## 库表数量与对象级上限

| 项目 | 数值 |
|---|---|
| 表级编辑的同步任务表数 | 同步对象为表级别且需编辑（如表列名映射）时，单次同步任务至多 1,000 张表；超出会请求报错，建议拆分任务或走整库同步 |
| 全量校验单表差异行数 | 超过 100,000 行差异终止该表校验 |
| 无主键无唯一索引表校验 | 数据超过 10,000 行不做校验 |
| 全量校验超时设置 | 1~72（小时） |
| 全量校验抽样百分比 | 10~100 的整数 |
| RPS 口径 | 一条 SQL 多行操作计多条记录变化；每次 COMMIT 也计一次记录变化 |

- 单任务库数量上限：官方未发布全局软上限（2026-11-18 复核「MySQL 为源数据同步使用限制」页，仅给表数量限制、无库数量限制；部分异构链路另有链路级限制，如 SQL Server→ADB 单任务最多 10 个库、ADB PostgreSQL 链路限单库）。

## 源库日志保留要求（MySQL/Binlog）

| 场景 | 最低保留 |
|---|---|
| 增量同步任务 | 源库本地 Binlog 保存 24 小时以上 |
| 全量 + 增量同步任务 | 源库本地 Binlog 至少保留 7 天以上（全量完成后可回调至 24 小时以上） |
| 参数要求 | 需开启 Binlog 且 `binlog_row_image` 为 `full`，否则预检查报错 |
| 违规后果 | 日志保留不足导致的任务失败/数据不一致不在 DTS SLA 保障范围内 |

- 方案概述（DTS 逻辑迁移使用限制，PolarDB-X 一键迁移引用）：https://help.aliyun.com/document_detail/2672864.html ｜ 复核：2026-11-16

## 运行期资源与数据形态限制

| 项目 | 官方口径 |
|---|---|
| 全量任务运行窗口 | 建议源/目标 CPU 负载 30% 以下的业务低峰期运行 |
| 目标库存储膨胀 | 并发写入无法保证顺序，目标库存储可能比源库大 5%~10% |
| DDL 禁令 | 库表结构任务和全量任务阶段禁止库/表结构变更 DDL，否则任务失败 |
| 目标库写入 | 运行期间除 DTS 外向目标库写入数据会导致不一致甚至失败 |
| 仅全量任务 | 不得向源库写入新数据，否则两端不一致 |
| 源/目标版本 | 同类型库建议同版本或低→高；高→低可能不兼容 |
| 列名映射 | 非全表同步/迁移时，目标库比源库缺少的列数据将丢失 |
| 校验性能影响 | 校验占用源/目标读资源，建议 CPU 负载 30% 以下执行 |
