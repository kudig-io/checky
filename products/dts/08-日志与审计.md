## 日志类型总表

| 类型 | 产生方 | 查看入口 | 默认保留期 | 是否计费 |
|---|---|---|---|---|
| 任务运行日志 + 任务时间轴 | DTS | DTS 控制台 > 实例详情 > 任务日志（数据同步 / 数据迁移 / 数据订阅；单独的校验任务只支持任务时间轴） | 📋 待补（官方未标注运行日志保留期） | 否（无单独日志计费项） |
| 运行日志·增量模块指标（generator / collector / replicator / ping / execute / rt 等） | DTS | 同上：任务日志 > 运行日志，可切换全量迁移 / 增量迁移 | 📋 待补 | 否 |
| Insight 主动运维记录 | DTS Insight 智能运维助手 | 任务日志页签「Insight 主动运维记录」；任务列表「查看原因 / 查看延迟原因」 | 📋 待补 | 否（智能诊断按每实例每日 10 万 Token 算力提供） |
| 报错与错误码 | DTS | 任务详情报错模块 + 任务日志；错误码对照见故障排查文档（DTS-RETRY-ERR 等） | 📋 待补 | 否 |
| 操作日志（实例操作记录） | DTS 控制台 | DTS 控制台左侧导航「操作日志」：展示所有地域，可按实例 ID / 任务名称 / 任务类型 / 操作结果 / 时间筛选 | 📋 待补（官方未标注保留期） | 否 |
| 系统事件 / 阈值事件（任务异常、恢复、延迟、运维腾挪） | 云监控 CloudMonitor | 云监控控制台 > 事件中心 > 系统事件；事件中心 > 事件订阅 | 📋 待补（官方未标注事件保留期） | —（官方未单列 DTS 事件计费项） |
| 审计管控事件 | 操作审计 ActionTrail | 操作审计控制台 > 事件查询 | 默认 90 天 | 操作审计本身免费；投递到 SLS / OSS 按目标产品计费 |

- 任务时间轴以时间线展示购买、配置、运行、故障、运行完成等关键节点；运行日志可按时间范围或任务状态筛选。
- DTS 控制台操作日志记录「对实例的操作、操作结果及操作者」，与账号级操作审计事件互补。

## 关键日志详表

**A. 任务运行日志（增量迁移 / 数据同步，「运行日志」页签字段）**

| 字段 | 类型 / 取值 | 含义 |
|---|---|---|
| `generator` | 计数 | 当前接收增量数据的总量 |
| `collector` | 计数 | 有效数据总量，包括心跳数据、同步对象的 DML 记录数、DDL 记录数 |
| `replicator` | 计数 | 同步的事务数（DML 和 DDL） |
| `ping` | 最小 / 平均 / 最大 | 网络延迟时间；`-1` 表示网络连接有问题，无法连接目标库 |
| `execute` | 最小 / 平均 / 最大 | 事务执行时间：事务拼装成 SQL 发往目标库执行且返回的时间 |
| `rt` | 最小 / 平均 / 最大 | 事务提交时间：事务执行时间与 Commit 的总时间 |
| `state` | IDLE / DML / DDL | 当前同步线程状态：空闲 / 正在同步 DML / 正在同步 DDL |
| `exceptions` | `connects` / `replicates` | 当前异常错误数：连接失败次数 / 同步线程写入目标库失败次数 |

- 任务时间轴节点（自下而上）：实例购买成功 → 任务启动成功 → 配置任务成功 → 预检查启动成功 → 结构迁移启动成功 → 全量迁移启动成功 → 数据同步启动成功 等任务阶段。

**B. 系统事件（任务异常 / 恢复，事件订阅内容字段）**

| 字段 | 类型 / 示例 | 含义 |
|---|---|---|
| `name` | `Instance:JobStatus.Abnormal:Executing`、`sync_job_abnormal`、`sync_job_restore`、`Instance:SystemMaintenance.Shift:Executed` | 系统事件名称（NameDesc） |
| `level` | CRITICAL / WARN / INFO | 事件等级：严重 / 警告 / 提示；文档中实例任务异常（JobStatus）为 WARN，同步任务异常示例为 CRITICAL |
| `status` | `failed` / `restore`；`Executing` / `Executed` | 任务状态：异常 / 已恢复（JobStatus 事件口径） |
| `eventDetail` | 结构化内容 | 事件详情：`dts_task_type` 任务类型、`dts_job_id` 任务 ID、`job_state` 任务状态、`err_code` 错误码、`err_msg_detail` / `message` 错误详细信息 |
| `resourceId` / `instanceId` | 默认以 `acs:dts:` 开头 | 影响的资源：含地域、账号 ID、实例 ID |
| `regionId` / `eventCategory` | 地域；`Exception` 等 | 实例地域与事件分类（EventType） |

**C. 操作日志（DTS 控制台「操作日志」）**

| 字段 | 含义 |
|---|---|
| 操作内容 | 对实例执行的操作（OpenAPI 对应 `ListUserOperationLog` 查询用户操作日志） |
| 操作结果 | 本次操作成功 / 失败 |
| 操作者 | 发起操作的账号或身份 |
| 操作时间 | 操作发生时间，默认按操作时间倒序展示 |
| 实例 ID / 任务名称 | 筛选维度之一 |
| 任务类型 | 数据迁移 / 数据同步 / 数据订阅 / 数据校验 |

**D. 审计管控事件（ActionTrail 管控事件结构）**

| 字段 | 含义 |
|---|---|
| `eventTime` | 事件发生时间（UTC 格式） |
| `eventName` | 事件名称；`eventType` 为 ApiCall 时即 API 名称（如 `CreateDtsInstance`、`ConfigureMigrationJob`、`ResetDtsJob`） |
| `eventType` | 事件类型：ApiCall / ConsoleOperation / ConsoleSignin / ConsoleSignout 等 |
| `eventRW` | 事件读写类型：Read / Write |
| `sourceIpAddress` | 事件发起的源 IP 地址 |
| `userIdentity` | 请求者身份信息（type 含 root-account / RAM 用户 / assumed-role 等） |
| `errorCode` | 云服务处理 API 请求发生错误时记录的错误码 |

## 投递与加工

| 通道 | 去向与参数 | 关键限制 / 额度 | 计费要点 |
|---|---|---|---|
| 任务日志 / 操作日志投递 | 📋 待补（官方未提供 DTS 任务日志、操作日志投递到 SLS / OSS 的功能文档，暂无官方投递入口可核） | — | — |
| 审计事件投递（创建跟踪） | 操作审计跟踪 → 日志服务 SLS LogStore 或对象存储 OSS Bucket | 单账号跟踪每地域 5 个；1 个跟踪最多配置 1 个 OSS Bucket；多账号跟踪可统一投递资源目录成员事件 | 操作审计本身免费；投递到 SLS / OSS / MaxCompute 按各自定价单独付费 |
| 云监控事件分发（事件订阅） | 轻量消息队列（原 MNS）、函数计算、URL 回调、日志服务 SLS | 云监控 > 事件中心 > 事件订阅；订阅类型为系统事件时产品选「数据传输」，阈值事件产品分类选「数据传输服务」 | 按目标产品定价单独计费 |
| 云监控 2.0 指标接入 | Prometheus 实例（默认存储位置 `RegionShare:{{workspaceName}}:{{regionId}}`） | 需开通可观测 Prometheus 版与企业云监控；暂只支持云监控指标接入；RAM 用户需 `AliyunCloudMonitorFullAccess` | 企业云监控实时导出费用 + 可观测监控 Prometheus 版费用 |

- 云监控事件的 `eventDetail` 含任务类型、任务 ID、错误码等字段，可在下游（MNS / 函数计算 / SLS）做二次加工与告警联动。

## 审计与合规

| 项 | 官方口径 |
|---|---|
| 接入方式 | 数据传输已与操作审计服务集成，可在操作审计中查询用户操作数据传输产生的管控事件 |
| 管控事件范围 | 创建 / 配置 / 启停 / 重置 / 释放任务与告警规则等，如 `CreateDtsInstance`、`ConfigureMigrationJob`、`ConfigureSynchronizationJob`、`CreateSubscriptionInstance`、`CreateJobMonitorRule`、`ModifyConsumptionTimestamp`、`ResetDtsJob`、`DeleteDtsJob` 等（官方事件清单） |
| 数据事件 | 官方事件清单仅列管控事件，未提供 DTS 数据事件列表（区别于 OSS 的 PutObject / GetObject 类数据事件） |
| 查询与留痕保留 | 默认每个阿里云账号保留最近 90 天操作事件；云上操作 10 分钟内可查；单账号仅支持当前地域 90 天内事件查询，`LookupEvents` 每秒最多 2 次 |
| 长期保存与合规 | 超过 90 天需创建跟踪，将事件投递到 SLS、OSS 或 MaxCompute 长期保存（等保 2.0 要求 180 天留存的场景）；数据回补任务可回补近 90 天数据 |
| 配额 | 单账号跟踪：每个地域 5 个；多账号跟踪：所有地域 1 个；1 个跟踪允许配置 1 个 OSS Bucket |
| 与产品内操作日志的关系 | DTS 控制台「操作日志」为产品内实例级记录（操作内容 / 结果 / 操作者）；ActionTrail 为账号级管控事件，两者互补 |
| 计费 | 操作审计本身免费；通过跟踪投递到 SLS / OSS / MaxCompute 时按各自定价单独付费 |

- DTS 系统事件（如 `SystemMaintenance.Shift` 计划内运维、DTS Insight 事件）经云监控事件订阅下发，事件分严重 / 警告 / 信息三级，可在任务管理中设置预约执行时间避开高峰。
