# MongoDB · 监控与告警

> 产品：云数据库 MongoDB 版 ｜ 口径：公共云 ｜ 复核：2026-11-17

## 核心监控指标

- 云监控（CloudMonitor）Namespace 固定为 `acs_mongodb`；Period 默认 60 秒，可设为 60 的整数倍。
- 副本集报警指标 Dimensions：`userId`、`instanceId`、`role`；分片集群另含 `subinstanceId`；Statistics 支持 Maximum / Minimum / Average。
- 单节点实例使用 `SingleNode` 前缀的独立 MetricName（如 `SingleNodeCPUUtilization`）。
- 控制台节点监控采集粒度最细 5 秒，监控数据保存 30 天；云监控 Period=60s 的监控数据存储 31 天。

| 指标（MetricName / 监控 key） | 含义 | 单位 | 统计周期 | 维度 |
|---|---|---|---|---|
| `CPUUtilization` / `cpu_usage` | 系统 CPU 与用户 CPU 使用率之和，表示实例业务负载 | % | 60s（Period 可为 60 的整数倍） | userId、instanceId、role |
| `MemoryUtilization` / `mem_usage` | 内存使用率（主要被 WiredTiger、连接与请求处理占用） | % | 60s | userId、instanceId、role |
| `DiskUtilization` / `disk_usage` | 磁盘使用空间占磁盘总容量的比例 | % | 60s | userId、instanceId、role |
| `IOPSUtilization` / `iops_usage` | IOPS 使用量与当前规格最大 IOPS 的比值 | % | 60s | userId、instanceId、role |
| `ConnectionAmount` / `current_conn` | 当前连接数（含副本集内部节点、mongos 与 shard 间连接） | Count | 60s | userId、instanceId、role |
| `ConnectionUtilization` / `conn_usage` | 当前连接数与实例最大连接数的比值 | % | 60s | userId、instanceId、role |
| `ReplicationLag` / `repl_lag` | 主备节点数据同步延时（心跳间隔 2s，-2~2 秒内均正常） | Seconds | 60s | userId、instanceId、role |
| `QPS` / `qps` | 每秒请求数（insert+delete+update+query+getmore+command） | Count/s | 60s | userId、instanceId、role |
| `NumberRequests` / `num_requests` | 处理的请求数 | Count | 60s | userId、instanceId、role |
| `OpQuery` / `query` | 查询操作次数 | Count/s | 60s | userId、instanceId、role |
| `IntranetIn` / `bytes_in` | 内网网络入流量 | Byte | 60s | userId、instanceId、role |
| `IntranetOut` / `bytes_out` | 内网网络出流量 | Byte | 60s | userId、instanceId、role |
| `InstanceDiskAmount` / `ins_size` | 实例占用磁盘空间量（云盘版含文件系统元数据） | Byte | 60s | userId、instanceId、role |
| `DataDiskAmount` / `data_size` | 数据盘使用空间（不含 local 库） | Byte | 60s | userId、instanceId、role |

- 磁盘使用率达到 80% 以上时，官方提示在控制台变更实例配置或排查空间使用率高的问题。
- 4.2 版本副本集/分片集群云盘版实例及单节点实例暂不支持 IOPS 使用量与使用率（控制台恒为 0）。
- 2024-08-12 起旧指标 `data_iops` 与 `log_iops` 合并为 `iops`，基于旧指标的告警阈值需更新。
- 分片集群可按组件（Shard/Mongos/CS）与角色（Primary/Secondary/ReadOnly）筛选实例监控。

## 官方默认与推荐告警

**A. 官方文档示例阈值（有官方出处）**

| 场景 | 阈值 | 出处 |
|---|---|---|
| 磁盘空间使用率 | 达到 80% 以上需变更实例配置或排查（官方处置提示，常被用作告警线） | 监控项说明（`disk_usage` 详细说明） |
| 磁盘空间使用率 | 空间使用率超 80% 需处理（通过 `db.stats()` 分析） | MongoDB 空间使用率高排查 |
| CPU 使用率 | 文档示例：「全部资源粒度的 MongoDB CPU 使用率大于 80% 报警」「实例粒度的主机 CPU 使用率大于 80% 报警」 | 设置阈值报警规则（创建报警规则示例） |
| CPU 使用率 | 阿里云告警示例：「提示您 CPU 使用率高于 80%」时按节点排查 | 节点监控 |

**B. 指标阈值类告警**

- 连接数使用率、IOPS 使用率、复制延迟（`ReplicationLag`）、网络流量、QPS、内存使用率等指标的推荐阈值：**官方未发布推荐阈值** 📋 待补（官方文档仅提供创建报警规则的操作与示例，未给出 MongoDB 推荐阈值；按阈值红线不收经验值）。
- MongoDB 默认/预置报警规则集合：官方未发布 MongoDB 默认报警规则 📋 待补。

**C. 事件类告警**

| 类型 | 说明 |
|---|---|
| 系统事件报警 | 云监控事件中心 > 系统事件，支持按事件类型、事件等级、关键词、SQL Filter 过滤后另存为报警；旧版系统事件报警规则不再升级，官方建议改用事件订阅功能 |
| 自定义事件报警 | 通过云监控自定义事件上报接口接入，按 1~5 分钟内累计发生次数触发 |
| 事件通知订阅 | 可通过云监控订阅 MongoDB 系统事件（如实例故障），支持短信/邮件/钉钉通知及函数计算/消息队列自动化处理 |

## 通知与渠道

| 渠道/机制 | 说明 |
|---|---|
| 通知方式 | 云监控报警服务支持电话、短信、邮件和 Webhook 地址；安装阿里云 App 可通过 App 接收报警通知 |
| 事件报警按级别通知 | Critical：电话+短信+邮件+WebHook；Warning：短信+邮件+WebHook；Info：邮件+WebHook |
| 报警联系人组 | 创建报警规则时选择已绑定报警联系人的联系人组 |
| 通道沉默周期 | 取值：5 分钟、15 分钟、30 分钟、60 分钟、3 小时、6 小时、12 小时、24 小时；沉默期内不重复发送，超期未恢复再次发送 |
| 生效时间 / 无数据处理 | 报警规则仅在生效时间内检查数据；无数据处理取值：不做任何处理（默认）、发送无数据报警、视为恢复 |
| 报警回调 | 公网可访问的 URL，云监控通过 POST 推送报警信息（仅 HTTP）；重试 3 次、超时 5 秒；需将官方指定 IP 段加入防火墙白名单 |
| 报警写入日志服务 | 开启后将报警信息写入指定 SLS Project 的 Logstore |
| 轻量消息队列（原 MNS） | 开启后将报警信息写入指定 Topic |
| 函数计算 | 报警发生时将通知发送至函数计算进行格式处理（需设置地域、服务、函数） |
| 弹性伸缩联动 | 报警发生时触发相应伸缩规则（需设置地域、伸缩组、伸缩规则） |
| 事件通知订阅 | 系统事件订阅支持短信、邮件、钉钉通知，以及函数计算、消息队列自动化处理 |
| 告警升级策略 | 官方未发布 MongoDB 告警升级（Escalation）策略 📋 待补 |
