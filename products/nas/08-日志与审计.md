## 日志类型总表

| 类型 | 产生方 | 查看入口 | 默认保留期 | 是否计费 |
|---|---|---|---|---|
| 访问日志（日志分析：通用型 NFS / 通用型 SMB / 极速型 NFS） | NAS + 日志服务 SLS | NAS 控制台 > 监控审计 > 日志分析；SLS 控制台（Logstore `nas-nfs` / `nas-smb-access-log` / `nas-extreme-nfs`） | 日志数据保存时间默认 30 天，可自行修改 | NAS 侧转储不额外收费；SLS 按使用功能计费（存储/读取/请求/加工/投递）或按写入数据量计费 |
| 管控审计事件（操作审计 ActionTrail） | 操作审计 ActionTrail | 操作审计控制台 > 事件查询 | 默认记录最近 90 天 | 操作审计本身免费；创建跟踪投递到 SLS/OSS 按目标产品计费 |
| 生命周期管理·数据取回任务记录 | NAS | NAS 控制台 / `ListLifecycleRetrieveJobs` API（状态：运行中、已完成、已取消、任务失败） | 📋 待补（官方未标注任务记录保留期） | 否（取回产生的读流量费用见 [07-计费与生命周期.md](07-计费与生命周期.md) 口径） |
| 回收站任务记录 | NAS | NAS 控制台 / `ListRecycleBinJobs` API | 📋 待补（官方未标注任务记录保留期） | 否 |
| 配置审计（资源配置变更历史） | 配置审计 Cloud Config | 📋 待补（未核到 NAS 专属配置审计页） | 📋 待补 | 📋 待补 |

- 日志分析功能开通后才开始采集，开通前已发生的操作不会被记录、无法查询。
- 专属 Logstore 不支持写入其他数据；请勿删除 NAS 相关的 SLS Project 和 Logstore。

## 关键日志详表

**A. 通用型 NFS 访问日志（Logstore `nas-nfs`，`__topic__` 固定为 `nas_audit_log`）**

| 字段 | 类型/示例 | 含义 |
|---|---|---|
| `SourceIp` | IP 地址 | 客户端 IP 地址 |
| `Volume` | 字符串 | 文件系统 ID |
| `Proc` | 编号 | NFSv3 Procedures 编号 |
| `OpList` | 编号 | NFSv4 Procedures 编号 |
| `RWSize` | 数值（字节） | 读写大小 |
| `NFSProtocolRc` | 数值 | NFS 协议返回码 |
| `AuthRc` | 数值 | 授权返回码 |
| `microtime` | 数值（微秒） | 请求发生时间 |

- 其余字段：`ArgIno`（文件系统 inode 号）、`ResIno`（lookup 的资源 inode 号）、`RequestId`、`User`（阿里云账号 ID）、`Vers`（NFS 协议版本）、`Vip`（服务端 IP）。

**B. 通用型 SMB 访问日志（Logstore `nas-smb-access-log`）**

| 字段 | 类型/示例 | 含义 |
|---|---|---|
| `OpName` | 字符串 | 请求操作名称 |
| `Host` | IP 地址 | 客户端 IP 地址 |
| `ObjectName` | 字符串 | 资源对象全路径名 |
| `Status` | 数值 | 请求返回状态 |
| `TotalTime` | 数值（毫秒） | 请求花费时间 |
| `UserSName` | 字符串 | 登录名 |
| `IOBytes` | 数值（字节） | IO 大小 |
| `VolumeID` | 字符串 | 文件系统 ID |

- 其余字段：`ArrivalTime`、`CompleteTime`（微秒）、`ConnID`、`Inode`、`RequestID`、`PersistentID`、`SessionID`、`UserID`、`UserSID`、`Opcode`。

**C. 管控审计事件（ActionTrail，NAS 事件结构）**

| 字段 | 含义 |
|---|---|
| `eventTime` | 事件发生时间 |
| `eventName` | 事件名称；`eventType` 为 ApiCall 时即 API 名称 |
| `eventSource` | 事件来源 |
| `eventType` | 事件类型（ApiCall / ConsoleOperation 等） |
| `eventRW` | 事件读写类型：Read / Write |
| `sourceIpAddress` | 事件发起的源 IP 地址 |
| `userIdentity` | 请求者身份信息 |
| `errorCode` | 云服务处理 API 请求发生错误时记录的错误码 |

- 极速型 NAS 访问日志存于 Logstore `nas-extreme-nfs`，字段与通用型 NFS 基本一致，另含 `Rc`（本次请求返回码）。

## 投递与加工

| 通道 | 去向与参数 | 关键限制 / 额度 | 计费要点 |
|---|---|---|---|
| 创建日志转储 | NAS 控制台 > 监控审计 > 日志分析 > 创建日志转储；配置文件系统类型与文件系统 ID；API `CreateLogAnalysis`（必填 RegionId、FileSystemId） | 首次需主账号授权 RAM 角色 `AliyunNASLogArchiveRole`，勿取消授权/删除角色；RAM 用户开通需先授权 | SLS 侧按使用功能计费或按写入数据量计费 |
| 专属 Project / Logstore | Project `nas-<账号ID>-<地域ID>`；Logstore：通用型 NFS `nas-nfs`、通用型 SMB `nas-smb-access-log`、极速型 `nas-extreme-nfs` | 请勿删除该 Project 与 Logstore，否则无法继续采集；专属 Logstore 不支持写入其他数据 | 同上；删除 Project 后不可恢复 |
| 专属仪表盘 | `nas-nfs-nas_summary_dashboard_cn`、`nas-nfs-nas_audit_dashboard_cn`、`nas-nfs-nas_detail_dashboard_cn`、`nas-smb-nas_audit_dashboard` | 仅通用型 NAS 支持；官方建议勿修改专属仪表盘 | 含在 SLS 计费内 |
| 查询分析与加工 | SLS 查询分析（可按 `Volume`、`SourceIp`、`Proc` 等字段检索）；采集后可执行查询分析、下载、投递、加工、创建告警 | 云产品日志通用操作入口 | 查询/索引/加工按 SLS 定价 |
| 审计事件投递 | 创建操作审计跟踪 → SLS 或 OSS Bucket | 单账号跟踪每地域 5 个；1 个跟踪最多配置 1 个 OSS Bucket；操作后 10 分钟内可在控制台查到 | 操作审计免费，投递目标按各自定价单独付费 |

- 官方未标注 NAS 日志跨账号投递能力 📋 待补。

## 审计与合规

| 项 | 官方口径 |
|---|---|
| 接入方式 | 文件存储 NAS 已接入操作审计（ActionTrail），统一记录云账号下用户登录及资源访问操作 |
| 覆盖通道 | 通过阿里云控制台、OpenAPI、开发者工具对 NAS 服务的访问和使用行为 |
| 留痕范围 | 官方列出 100+ 审计事件，覆盖资源全生命周期操作，如 `CreateFileSystem`、`DeleteFileSystem`、`CreateMountTarget`、`ModifyMountTargetAccessGroup`、`CreateSnapshot`、`CreateLifecyclePolicy`、`CreateLogAnalysis`、`EnableRecycleBin`、`SetDirQuota`、`CreateFile` 等 |
| 查询与保留 | 默认为每个阿里云账号记录最近 90 天操作事件；不创建跟踪则无法追溯 90 天以前的事件 |
| 可见延迟 | 用户操作后 10 分钟内可通过控制台/API 查询；OSS 存储中同样 10 分钟内可访问 |
| 长期保存 | 超过 90 天需创建跟踪，将事件投递到 SLS 或 OSS（等保 2.0 要求 180 天留存的场景） |
| 配额 | 单账号跟踪每地域 5 个；多账号跟踪所有地域 1 个；1 个跟踪允许 1 个 OSS Bucket；LookupEvents 每秒最多 2 次 |
| 文件级访问审计 | 通过日志分析（SLS）记录 NAS 访问日志（NFS/SMB 字段级），与 ActionTrail 管控事件互补 |
| 计费 | 操作审计本身免费；投递到 SLS/OSS 按目标产品定价单独付费 |

- 历史事件如需在 90 天之外查询，官方口径为提交工单申请开启相关权限。
