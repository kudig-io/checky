## CU 定义与换算

| 项 | 数值 |
|---|---|
| 1 CU | = 1 核 CPU + 4 GiB 内存 + 20 GB 本地存储（放日志、系统检查点等） |
| 已使用 CU 公式（工作空间） | MAX（⌈CPU 总和⌉，⌈内存总和/4⌉） |
| 作业所配置 CU 数 | MAX（JM 和 TM 的 CPU 总和，JM 和 TM 的内存总和/4），比值分别向上取整 |

## CU 处理能力（官方压测口径）

| 处理场景 | 1 CU 每秒处理能力 |
|---|---|
| 简单流式压测（过滤、清洗） | 40000~55000 条 |
| 复杂流式压测（聚合、复杂 UDF、JOIN、GROUP BY、窗口） | 5000~10000 条 |

说明：仅限实时计算内部处理能力，不含对外读写；受 LogService 配额、RDS 连接数/TPS 等上游限制。使用窗口函数时 CU 消耗高于简单作业，官方建议至少购买 4 CU。

## 资源模式：基础（粗粒度）vs 专家（细粒度）

| 资源模式 | 分配方式 | 适用 | 限制 |
|---|---|---|---|
| 基础模式（粗粒度） | 静态：给定每 TM 总资源（CPU+JVM 总内存），按每 TM Slot 数均匀分配 | 大多数简单作业 | 所有作业类型可用 |
| 专家模式（细粒度） | 动态：按 Slot 共享组（SSG）配置，系统计算每 Slot 规格并动态申请 TM/Slot | 复杂作业、算子级精细控制 | 仅 SQL 作业支持；改 SQL 或资源后需重新生成资源计划图 |

资源配置后需重启作业生效。

**来源**：
- 配置作业资源：https://help.aliyun.com/zh/flink/user-guide/configure-deployment-resources ｜ 复核：2026-11-16

## JM/TM 规格档位

| 配置项 | 基础模式 | 专家模式 |
|---|---|---|
| JobManager CPU | 最小 0.5 Core，建议 1 Core，最大 16 Core | 最小 0.25 Core，最大 16 Core |
| JobManager Memory | 最小 2 GiB，最大 64 GiB（建议 4 GiB；水位长期 >80% 有 OOM 风险） | 最小 1 GiB，最大 64 GiB |
| TaskManager CPU | 最小 0.5 Core，建议 1 Core，最大 16 Core | 按 Slot 共享组配置 CPU/Heap/Off-Heap |
| TaskManager Memory | 最小 2 GiB，最大 64 GiB | 按 Slot 共享组配置 |
| 每 TM Slot 数 | 手填（或 numberOfTaskSlots，优先级更高） | 无此配置项 |

- 超过默认 TM CPU/内存最大值需提交工单。
- JVM Overhead 比例 `taskmanager.memory.jvm-overhead.fraction` 默认 0.1（占 TM 总内存 10%）；建议在 TM 总内存基础上至少预留 400 MB 供操作系统 Page Cache。
- 批处理补充：每 CPU 核配额 20 GiB 磁盘；TM 最低磁盘 20 GiB、最大 200 GiB；批作业默认每 TM 1 个 Slot，可增至 2 或 4。

## CU 与并行度换算

| 关系 | 公式/示例 |
|---|---|
| 总 CU 与并发度 | 总 CU 消耗 = 并发度 × 每个 Task 分配的 CU 数（非 1:1，取决于 Slot 规格） |
| 1 Slot = 1 CU 条件 | 每 Slot 配置 1 Core + 4 GiB 时，1 Slot 消耗 1 CU；并发度 10 ≈ 10 CU |
| 实际 TM 数 | = ⌈并发度 / 每个 TM Slot 数⌉ |
| 每 TM 可分配 Slot 数 | = ⌈并发度 / 实际 TM 数⌉ |
| 官方示例 | 并发度 12、每 TM 4 Slot → 实际 3 个 TM、每 TM 4 Slot（JM/TM 均 2 Core + 4 GiB） |

## 选型速查

| 场景 | 建议 |
|---|---|
| 简单过滤/清洗类流作业 | 基础模式；1 CU 级别可起，实际按并发度 × Slot 规格估算 |
| 窗口/聚合/JOIN 类作业 | 官方建议至少 4 CU |
| 复杂 SQL、算子负载不均（如 sink Busy 反压） | 专家模式 + 多 SSG 模式，单独调大该算子 Slot 的 CPU/内存 |
| 流作业频繁重启、全量同步阶段 | 每 TM Slot 数设为 1，用并发度调优，1 Core 4 GiB 规格 + 并发数如 10 测试 |
| 批处理作业 | 每 Slot 1 Core + 4 GiB；关注 TM 磁盘（每核 20 GiB，上限 200 GiB）；可用「最大 Slot 个数」限制资源 |
| Source 节点并发度 | 与分区数成比例（能整除），如 Kafka 16 分区 → 16/8/4 |
