## 单作业资源上下限

| 参数 | 下限 | 建议 | 上限 |
|---|---|---|---|
| JobManager CPU（基础模式） | 0.5 Core | 1 Core | 16 Core |
| JobManager Memory（基础模式） | 2 GiB | 4 GiB | 64 GiB |
| TaskManager CPU（基础模式） | 0.5 Core | 1 Core | 16 Core |
| TaskManager Memory（基础模式） | 2 GiB | — | 64 GiB |
| JobManager CPU（专家模式） | 0.25 Core | — | 16 Core |
| JobManager Memory（专家模式） | 1 GiB | — | 64 GiB |

- 官方明确「每个 JM 和 TM 至少 0.5 个 CPU 核心和 2 GiB 内存才能保证作业稳定运行」。
- 超过默认 TM CPU/内存最大值需提交工单。
- 单个作业（Job）的 CU 总量上限：官方使用限制页未公布单作业 CU 硬上限（2026-11-18 复核该页，仅规定单次开通 ≤1000 CU、单工作空间 5000 项目空间）；实际受工作空间/项目空间配额与队列资源量约束。

## 并行度（并发度）限制与规则

| 项 | 官方口径 |
|---|---|
| 并发度定义 | 作业全局并发数；资源配置页配置，或 SQL WITH 参数针对特定算子设置 |
| `SET 'parallelism.default' = 'N'` | 无效，平台不支持通过 SET 命令动态设置全局并发度 |
| 并发度与 CU | 总 CU = 并发度 × 每 Task CU 数；每 Slot 1 Core+4 GiB 时 1 Slot = 1 CU，并发度 10 ≈ 10 CU |
| Source 并发度建议 | 与分区数成比例（能整除），如 Kafka 16 分区 → 16/8/4 |
| 批处理自动并行度（VVR 8.0+，默认开启） | `min-parallelism` 默认 1；`max-parallelism` 默认 128（未配置时取全局并行度）；`avg-data-volume-per-task` 默认 16MiB；`default-source-parallelism` 默认 1 |
| 批处理「最大 Slot 个数」 | 可配置，用于限制作业可用的最大资源量 |
| 流作业 Slot 行为 | 默认开启 Slot 共享，启动时一次性申请等于全局并行度的 Slot 数 |
| 并行度硬上限（流作业） | 官方未公布流作业全局并行度最大值（2026-11-18 复核使用限制页）；批处理自动并行度 max-parallelism 默认 128 |

## 状态后端（StateBackend）

| 项 | 官方口径 |
|---|---|
| 默认状态后端 | GeminiStateBackend（企业级 KV 存储引擎，LSM 架构，存储计算分离，不依赖本地盘） |
| 对比对象 | RocksDBStateBackend |
| Nexmark 对比（Gemini vs RocksDB，TPS/Core） | q4：83.63K vs 53.26K（+57.02%）；q5：84.52K vs 57.86K（+46.08%）；q8：468.96K vs 361.37K（+29.77%）；q9：59.42K vs 26.56K（+123.72%）；q11：93.08K vs 48.82K（+90.66%）；q18：150.93K vs 87.37K（+72.75%）；q19：143.46K vs 58.5K（+145.23%）；q20：75.69K vs 22.44K（+237.30%） |
| 官方结论 | 约一半用例性能领先 RocksDB 70% 以上 |
| KV 分离（双流/多流 Join） | 开启后吞吐提升 50%~70% 以上，资源利用率平均提升 50%，典型场景 100%~200%（双十一业务验证口径） |

- 企业级状态后端存储介绍：https://help.aliyun.com/zh/flink/user-guide/geministatebackend ｜ 复核：2026-11-16

## Checkpoint 与状态参数

| 参数 | 官方默认/规则 |
|---|---|
| 系统检查点间隔 | 需手动配置；官方说明「如果不填写，将会关闭系统检查点」，即无默认间隔数值（2026-11-18 复核配置作业部署信息页） |
| 系统检查点超时时间 | 默认 10 分钟，到达后检查点生成失败 |
| 两次检查点最短间隔 | 可配置；检查点最大并行度为 1 时保证两检查点间有最短间隔 |
| State 数据过期时间（TTL） | 默认 36 小时（云上最佳实践值；开源默认 0 = 永不过期） |
| 作业过期时间 | 未设置过期时间的作业默认 1.5 天；算子级 TTL 默认跟随作业过期时间 |
| 算子 State TTL | 仅 VVR 8.0.7 及以上支持；仅状态算子支持；近似清理机制 |
| 作业级重启策略 | 默认 Fixed Delay（开检查点时）；未开检查点则不重启；可选 No Restarts / Failure Rate |
| 任务级故障恢复 | `jobmanager.execution.failover-strategy` 默认 region（只重启最小任务集合），可选 full |

## 日志与运行参数

| 参数 | 官方默认 |
|---|---|
| 日志归档 | 默认开启 |
| 归档日志有效期 | 默认 7 天 |
| 根日志级别 | TRACE / DEBUG / INFO / WARN / ERROR（可按类名单独设置） |
| `jobmanager.memory.off-heap.size` | 默认 128 MB（Paimon 大同步场景 JM Direct Buffer OOM 时建议调至 512 MB 或更大） |
| `taskmanager.memory.jvm-overhead.fraction` | 默认 0.1（占 TM 总内存 10%） |
| `numberOfTaskSlots` | 在「其他配置」中设置，与界面「每个 TM Slot 数」作用相同但优先级更高 |
| GC 类型 | 不支持通过 `env.java.opts` 修改（如 `-XX:+UseG1GC`），需提工单 |
