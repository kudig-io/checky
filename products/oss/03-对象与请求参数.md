# OSS · 对象与请求参数

> 产品：对象存储 OSS ｜ 口径：公共云 ｜ 复核：2026-11-18

## 对象（Object）大小上限

| 上传方式 | 单个文件大小上限 |
|---|---|
| 简单上传、表单上传、追加上传 | 5 GB |
| 分片上传 | 48.8 TB |

- 控制台仅支持重命名 1 GB 及以下文件；1 GB 以上建议用 SDK 或 ossutil。
- 默认同名上传会覆盖已有文件；可用 Header `x-oss-forbid-overwrite: true` 或开启版本控制防覆盖。
- 分片上传任务无过期时间限制，支持暂停和恢复；未调用 Abort 的碎片文件保留在 Bucket 中并持续产生存储费用。

- OSS使用限制及性能指标：https://help.aliyun.com/zh/oss/user-guide/limits ｜ 复核：2026-11-16
- 分片上传：https://help.aliyun.com/zh/oss/user-guide/multipart-upload ｜ 复核：2026-11-16

## 分片上传参数

| 限制项 | 数值 |
|---|---|
| 单个文件大小 | 不超过 48.8 TB |
| 分片数量 | 1~10,000 个 |
| 单个分片大小 | 最小 100 KB，最大 5 GB；最后一个分片允许小于 100 KB |
| 单次 ListParts 返回分片最大数量 | 1,000 个 |
| 单次 ListMultipartUploads 返回事件最大数量 | 1,000 个 |

流程与接口：

1. InitiateMultipartUpload → 获取 Upload ID（任务标识）。
2. UploadPart 分片并发上传（每分片对应 1 次 PUT 请求，分片数 = PUT 请求数）。
3. CompleteMultipartUpload 按序号合并为完整对象。
4. 中断清理：AbortMultipartUpload / 控制台碎片管理 / 生命周期清理过期碎片。
- ossutil `cp` 对超过 100 MiB 的文件自动启用分片上传；OSS 控制台暂不支持分片上传操作。
- 分片存储费按分片存储类型、实际大小、时长收取，无最小计量单位限制；合并或删除后停止计费。

**来源**：
- 分片上传（配额与限制/计费说明）：https://help.aliyun.com/zh/oss/user-guide/multipart-upload ｜ 复核：2026-11-16

## 存储空间（Bucket）命名规则

| 规则 | 要求 |
|---|---|
| 全局唯一 | Bucket 名称在 OSS 范围内必须全局唯一 |
| 字符集 | 只能包括小写字母、数字和短划线（-） |
| 开头结尾 | 必须以小写字母或者数字开头和结尾 |
| 长度 | 3~63 个字符 |
| 可变性 | 创建后名称、地域、存储类型不支持修改 |

- 正确示例：`examplebucket1`、`test-bucket-2021`、`aliyun-oss-bucket`。
- 错误示例：`Examplebucket1`（大写）、`test_bucket_2021`（下划线）、`aliyun-oss-bucket-`（结尾短划线）。

**来源**：
- 存储空间命名：https://help.aliyun.com/zh/oss/user-guide/bucket-naming-conventions ｜ 复核：2026-11-16

## 对象命名（ObjectKey）

- ObjectKey、Key、ObjectName 是同一概念：包含文件后缀在内的完整路径，如 `abc/efg/123.jpg`。
- 对象由 Bucket 内唯一的 Key 标识；OSS 内部扁平存储，无真实目录层级，`/` 仅为逻辑分隔。
- 大量上传时避免顺序前缀（时间戳/字母序），否则请求集中到特定分区导致请求速率下降。
- ObjectKey 长度/字符集：长度 1~1023 字节、须为 UTF-8 编码，且不以 `/` 或 `\` 开头（官方错误码 0016-00000001/0016-00000002 口径，2026-11-18 复核）。

- OSS使用限制及性能指标（顺序前缀）：https://help.aliyun.com/zh/oss/user-guide/limits ｜ 复核：2026-11-16

## API 请求分类（计费口径）

OSS 所有访问与管理操作（API/SDK/控制台/ossutil/ossbrowser、内网或外网、公共读或私有）实质都是 OSS API 调用，按实际调用次数收取请求费用。返回码 2xx、3xx 的请求产生请求费用；4xx、5xx 不产生请求费用。

| 请求类 | 计费项 Code | 代表 API |
|---|---|---|
| Put 类 | PutRequest | PutBucket、PutObject、CopyObject、AppendObject、DeleteObject、DeleteMultipleObjects、PostObject、RestoreObject、InitiateMultipartUpload、UploadPart、UploadPartCopy、CompleteMultipartUpload、AbortMultipartUpload、PutBucketLifecycle、PutBucketVersioning、PutBucketPolicy、PutBucketReplication、ListObjects/ListObjectsV2、ListParts、ListMultipartUploads 等 |
| Get 类 | GetRequest | GetObject、GetBucketAcl、GetBucketLocation、GetBucketInfo、GetBucketLogging 等读取类操作 |
| 冷归档取回请求 | CAStdRetrievalRequest / CAHighPriorRetrievalRequest / CABulkRetrievalRequest | 按解冻优先级分三档；解冻 1 个文件 = 1 次取回请求，与文件大小无关 |
| 深度冷归档取回请求 | DeepCAStdRetrievalRequest / DeepCAHighPriorRetrievalRequest | 两档；解冻 1 个文件 = 1 次取回请求 |

特殊请求计费逻辑：

| API | 计费逻辑 | 示例 |
|---|---|---|
| ListObjects / ListObjectsV2 | 调用一次算一次 Put 类请求；次数取决于每次返回数量 | 10,000 文件：默认每次 100 个 → 100 次；max-keys=1000 → 10 次 |
| DeleteMultipleObjects | 调用一次算一次 Put 类请求 | 10,000 文件：每次 1000 个 Key → 10 次 |
| CommitTransition（生命周期转类型） | 一次调用算一次 Put 类请求，按命中文件个数计费 | 命中 1000 个 → 1000 次 Put 请求 |
| ExpireObject（生命周期删除） | 一次调用算一次 Put 类请求，按命中文件个数计费 | 命中 1000 个 → 1000 次 Put 请求 |

- 中国大陆各地域：生命周期删除低频/归档/冷归档对象的 Put 类费用高于删除标准存储；删除深度冷归档对象不收 Put 类费用。
- 中国香港及海外地域：生命周期删除各存储类型对象均不收 Put 类请求费用。
- CopyObject 按 Object **源**存储类型计 PUT 请求费；UploadPartCopy 按**目标**存储类型计费。
- OSS Table Bucket 公测期间不收费，自北京时间 2026 年 12 月 30 日起商业化收费。

**来源**：
- 请求费用：https://help.aliyun.com/zh/oss/api-operation-calling-fees ｜ 复核：2026-11-16

## 删除与覆盖限制

| 项 | 限制 |
|---|---|
| 控制台一次删除 | 最多 100 个文件 |
| SDK 一次删除 | 最多 1,000 个文件 |
| ossutil / ossbrowser 一次删除 | 无限制 |
| 同名覆盖 | 默认覆盖；Header `x-oss-forbid-overwrite: true` 可禁止（版本控制开启/暂停时不生效） |
| 数据恢复 | 文件删除后无法恢复；当前 OSS 不提供回收站，找回依赖版本控制 |
