## 最大连接数口径

- 规格表中的最大连接数是**单个节点**的连接数，不是集群总连接数。
- `max_connections` 为可修改集群参数，取值范围 1~200000；默认值随规格不同。
- 只读节点数量与最大连接数无关，增加只读节点不能提升单节点连接数；需要更大连接数应升配规格。
- 数据库代理（Proxy）本身无最大连接数限制，限制由后端计算节点规格决定；未开事务级连接池时，每条客户端连接需在主节点和所有只读节点各建一条对应连接。
- PolarDB 不支持超级用户；数据库个数上限 1 万个（受文件数量限制）；单表最大数据量 64 TB。

## 并行查询与特性参数

| 特性 | 官方口径 |
|---|---|
| 弹性并行查询 ePQ | 单机并行：计算节点仅 MySQL 8.0.1；只读节点 8.0.1/8.0.2；多机并行（跨节点）：8.0.2 |
| 代理开启并行查询 | 仅 8.0 版本集群在「配置数据库代理」时支持开启并行查询和设置并行度 |
| 列存索引 IMCI | 仅 8.0.1/8.0.2 支持；行存/列存按 SQL 预估执行代价阈值自动分流 |
| 全局一致性（高性能模式） | 企业版 8.0.2（小版本 ≥8.0.2.2.19）或 8.0.1（≥8.0.1.1.29）；相对最终一致性性能损耗控制在 10% 以内（8 核 32 GB sysbench oltp_read_write 实测） |
| 事务拆分 / 连接池 / 一致性级别 | 集群地址（Proxy）配置项，见 05-网络参数 |
| Serverless 弹性单位 | PCU：1 PCU ≈ 1 核 2 GB；单次弹性最小 0.5 PCU；固定规格集群 Serverless 弹升 0~16 PCU/节点，只读节点伸缩 0~15 个 |

## 常见性能口径问答

| 问题 | 官方答案 |
|---|---|
| 增加只读节点能解决写压力大吗 | 不能 |
| IOPS 是否集群内争抢 | 每个节点按规格设置 IOPS，节点间独立隔离互不影响 |
| 开启 Binlog 性能影响 | 不影响查询；读写均衡库中开启后对性能影响一般不超过 10% |
| 开启 SQL 洞察性能影响 | 无影响 |
| 高速网络协议 | 计算/存储节点之间及存储多副本之间使用双 25 Gbps RDMA |
| 外网连接带宽上限 | 10 Gbit/s |
